# 开发测试说明

本目录保存 JSON 输入、预期结果和测试脚本，供开发者检查节点、连线、保存、运行及错误处理。**测试 UE 工程、生成资产和本机报告不随仓库提供。** 普通用户安装插件请看[安装指南](../Docs/Installation.md)。

## 运行前准备

1. 安装官方 UE 5.3.2，并准备与测试代码匹配的插件 DLL。
2. 使用专用、可丢弃的 UE 工程；不要把生产工程当作负例测试对象。
3. 从实际加载的插件导出节点目录，必要时读取材质函数签名和父材质参数。目录摘要、DLL 和资源摘要必须配套。
4. 检查所选脚本的参数、固定路径和工程要求，再创建新的运行目录。
5. 保存实际输入、日志和结果。失败后先确认已有写入，再决定是否继续。

这些脚本保留开发工作区的目录约定，部分引擎路径仍写在脚本中，尚不是通用 CI 命令。clone 后仅有源码和用例并不足以直接运行全部检查。`RunGraphRegression.py` 和 `RunPrototypeRegression.py` 能创建部分空测试工程；其他脚本需要现有专用工程、对应调用报告或已生成资产。运行前应按源码核对，不能假定缺失的本机文件会随仓库出现。

## 主要运行器

| 脚本 | 作用与必要输入 |
| --- | --- |
| [RunGraphRegression.py](../Scripts/RunGraphRegression.py) | 读取 `Cases.json`，绑定实际目录并检查预检、生成、编译、保存和独立重开；需 `--run`、`--catalog`，可用 `--fixtures`、`--case`、`--plugin-directory`、`--function-signature` |
| [RunBlueprintMotionChecks.py](../Scripts/RunBlueprintMotionChecks.py) | 消费已完成图测试的结果和 `RuntimeCases.json`，在新进程 PIE 中检查 Actor 变换和消息；普通矩阵使用 `--run`、`--graph-run` |
| [RunGraphSceneChecks.py](../Scripts/RunGraphSceneChecks.py) | 检查固定场景与材质画面；依赖对应场景配置和生成结果 |
| [程序控制测试](PluginControl/Readme.md) | 检查 CLI、活动编辑器、会话身份、草稿、调用状态和关闭流程 |
| [固定最小回归](Regression/MinimalRegression.md) | 固定输入格式、拒绝行为和两个最小资产的回归检查 |

`--prepare-only` 只准备输入及测试工程，不表示 UE 已运行。使用 `--case` 时还需包含其依赖项和布局对照项；选定子集的结果只适用于这个子集。

## 输入文件的含义

- `Cases.json` 指定输入文件、前置依赖和预期结果。拒绝例属于故意错误的数据，不是用户使用示例。
- `RuntimeCases.json` 是运行检查的独立期望，不能用生成报告反过来生成期望值。
- `VisualConfig.json` 等文件指定画面检查条件，生成成功不会自动满足画面预期。
- `CATALOG_DIGEST_FROM_REAL_ENGINE` 和全零父材质 SHA 是模板占位符，不能直接粘贴到插件执行。运行器将实际绑定后的输入另存，源模板保持不变。
- `preserveCatalogDigest=true` 的用例故意使用固定摘要来检查能力范围，不应替换成当前摘要让它通过。

## 按改动选择检查

| 改动范围 | 相关检查 |
| --- | --- |
| JSON 字段、类型和路径 | 合法输入、重复键、未知字段、错误类型、路径与同名拒绝 |
| 节点、默认值或连线 | 精确类名和引脚、参数边界、实际结构回读、编译、保存与独立重开 |
| 布局 | 显式位置保持、自动布局、数组乱序、坐标范围与必要的编辑器观察 |
| Actor 行为 | 实际位置、旋转、缩放和消息，不只检查图能否编译 |
| 材质和资源 | 参数、采样器、函数签名、父文件摘要与需要的实际画面 |
| CLI/MCP 与编辑器控制 | 身份、权限、修订、重复调用、超时未知状态、原调用查询和正常关闭 |
| 安装与发布 | 匹配引擎、插件装入、AI 环境、连接、停用插件后的资产使用及所声明的平台 |

## 记录结果

将通过、失败、未执行和不适用分开记录，并写明引擎、插件、输入和实际运行范围。已有资产及失败报告应保留；不能删用例、放宽预期或重命名目标掩盖失败。

预检、编译、保存、独立重开、实际运行、画面和打包分别判断。测试数量或配置文件的存在不代表全部测试通过。[研究场景索引](ResearchTestMap.md)还包含尚未实现的设计方向，不应并入当前版本的通过数量。
