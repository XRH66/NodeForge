# 发布包与版本约定

NodeForge 的第一个可用版本为历史 **v0.1.0**；当前正式首版为 **v1.0.0**。用户在同一个 Release 中下载插件和可选 AI 接入包。

## 用户下载什么

| 附件 | 用途 |
| --- | --- |
| `NodeForge-1.0.0-UE5.3.2-Windows.zip` | UE 插件、普通安装说明和入门示例 |
| `NodeForge-AI-1.0.0-Windows.zip` | AI 连接服务、固定运行环境、安装工具和离线文档 |
| `ReleaseManifest.json` | 版本、平台、文件名、下载地址及配套关系 |
| `Checksums.sha256` | 下载文件的 SHA256 校验值 |

普通用户只下载插件 ZIP，复制到引擎 `Engine/Plugins/Marketplace` 后在 UE 中启用。AI 接入可以稍后补装；接入包使用同一份插件，不包含第二套插件核心。AI 接入包自带 Python，无需另装运行环境。

GitHub 自动生成的 `Source code` 压缩包供开发者阅读源码，不是插件安装包。

## 版本与环境

v1.0.0 的插件和 AI 接入包均适用于 Windows 64 位、官方 UE 5.3.2。安装工具检查引擎版本和已安装插件，避免把不匹配的组件放在一起。

Release 标题使用 `NodeForge v1.0.0`，标签使用 `v1.0.0`。后续发布使用语义化版本号：修复使用补丁版本，新增兼容功能使用次版本，有不兼容变化时在版本说明中明确列出。对外名称不使用内部构建编号。

文件名包含版本与平台；插件文件名另包含支持的 UE 版本。用户始终从同一 Release 取得匹配附件，不需要推断内部文件之间的关系。

## Release 页面写什么

页面按以下顺序组织：

1. 一句话说明本版用途及支持环境。
2. 插件和 AI 接入包的直接下载链接。
3. [普通安装](Installation.md)、[快速开始](GettingStarted.md) 和 [AI 接入](AiInstallation.md)。
4. 本版功能、用户可见的改动及实际限制。
5. 供自动安装工具读取的清单和校验文件说明。

技术细节放在 [开发说明](RepositoryGuide.md) 和版本手册中。用户文档中的操作应使用下载包提供的文件，不依赖维护者电脑上的路径或工程。

## 仓库与附件的分工

Git 保存源码、协议、节点目录、文档、示例、测试脚本以及依赖和许可清单。Release 提供编译插件及 AI 所需的固定运行环境。UE 工程、用户资源、会话配置、缓存和本机运行记录不随发布上传。

普通插件包使用 `portablePlugin` 布局，默认安装到引擎 `Engine/Plugins/Marketplace/NodeForge`，同包保留引擎直接目录和工程 `Plugins/NodeForge` 的高级用法。同一工程不能同时发现多份同名插件。AI 接入工具把服务、运行环境和文档补充到同一插件位置，客户端配置一次，之后正常打开工程连接；保留客户端的其他配置。

打包工具与所需输入见 [源码仓库说明](RepositoryGuide.md)。文件清单与下载校验值必须来自实际产物，不能只改版本名称后沿用不匹配的数值。

先建立同版 draft，上传普通包取得真实附件 ID，再制作引用该附件的最终 AI 包。发布前将新 tag 固定到与最终源码、资源、脚本和公开文档一致的 commit，完整下载附件核对字节并实际安装。新发行和原站闭合后才按已批准清单撤下旧 Release；撤下前完整归档旧正文、tag/commit 和每个附件，不删除旧 tag、本地资料与报告。

## 发布前核对

确认两个 ZIP 可以解压，文件名、版本、引擎、平台和 SHA256 与发布清单一致。检查安装指南的链接及文档引用，确认下载所需文件都在当前 Release 中。

安装检查应覆盖新装普通插件、补装 AI 和安装后的实际连接。说明应明确已支持的客户端配置格式及尚未支持的环境。要向所有人提供下载时，仓库、附件和指南必须具有相应访问权限；标题或版本名称不会自动改变可见性。
