# 兼容与旧版迁移

v1.1.1 只支持官方 UE 5.3.2 / Windows 64 位。普通与 AI 两包必须来自同一 Release；复制位置支持引擎 Marketplace、引擎直接 Plugins 和高级工程 Plugins，同名副本不得并存。

## 从 v1.0.0 或 v1.1.0 升级

1. 保留旧包、客户端配置及原安装/绑定收据，保存并正常关闭相关编辑器。
2. 下载 v1.1.1 普通插件；使用 AI 时另下载同版 AI 接入包。引擎尚无插件时，将新普通包复制到 `Engine/Plugins/Marketplace/NodeForge`；不要把新 DLL 覆盖在旧版目录内，也不要启动存在两份副本的工程。
3. 使用 AI 时运行新版 AI 安装工具，指定引擎和客户端配置。工具只迁移能准确证明属于旧版 NodeForge 的条目，保留其他客户端配置。旧工程插件、原绑定和旧 ClientState 在这一步仍须可读取；未知同名条目会拒绝覆盖。
4. 对旧工程级安装，按旧原始绑定收据使用旧准备器的 rollback 恢复旧绑定，再把属于自己的旧插件文件夹移到工程和引擎插件扫描范围之外保留。不要删除旧资产、报告或收据，不复制旧会话到新工程。
5. 正常打开工程，启用新插件并确认当前路径；让客户端重新加载配置，读取文档，再连接实际工程。

已有新版工程级安装且要继续保留时，使用 `-Project` 与 `-PluginDirectory` 的高级入口；不要再装一份同名引擎插件。

## 同版更新与移动

同版重复安装幂等。已完成的同版配套文件更新需提供原完成收据 `--upgrade-receipt`；部分写入先查原收据，可用 `--resume-receipt` 接续。不同核心或未知已改文件不能通过这两个参数强制覆盖。

引擎安装位置变化需要重新核安装并更新客户端固定入口；同一引擎中正常打开不同工程无需重新安装。首次页核当前工程身份，状态与日志分别位于各工程 `Config/NodeForgeInstallation` 和 `Saved/NodeForge`，不要跨工程复制绑定。

本版保留 JSON v2/v3、节点范围、来源证明、create-only、未知写入停止和原 CLI 独立保存核验。新输入使用当前目录，不只替换目录摘要绕过准入。

[安装插件](../User/PluginInstallation.md) · [连接 AI](../User/AiInstallation.md) · [已知限制](KnownIssues.md)

客户端应用代码和 UI 已更新，升级需用同版两包及实际安装收据；保留旧配置、原资产/报告。不要在正在使用的 DLL 上覆盖，不能用仅更新清单伪装核心升级。同一工程的已应用设置保持，面板改版不清空真实数据。

调用回收需要本版原生 DLL 与桥 0.4.4。正在运行的旧编辑器须由使用者保存并正常关闭后升级，再正常打开并核对实际加载身份；不得热替换正在使用的 DLL。JSON v2/v3、节点目录、贴图通道和既有资产保持。
