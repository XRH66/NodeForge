# 故障记录与恢复

安装或调用中断后，先确认已经发生了什么，再继续操作。版本、工程和调用状态都应从当前文件与工具返回读取。

## 保留哪些信息

- NodeForge 版本、UE 版本、插件位置和目标工程。
- 当前 `handle`、`callId`、草稿修订，以及原始输入和报告。
- 已产生的资产、请求收据、文件 SHA 和可能的部分写入。
- 原生状态、错误码、尚未完成的检查和下一步要确认的事项。

对外提交问题前移除密钥、私有会话文件和无关个人路径。提供最短复现步骤、预期结果与实际结果，便于其他人定位。

## 如何继续

`pending` 或 `unknown` 时用原 `callId` 查询，不用新的请求或资产名重复生成。连接中断后也先查明原调用是否执行；重新连接成功并不证明之前没有写入。

只有确认调用尚未发送或执行、且原因已处理后，才重新提交。已有部分结果时保留原文件，按 [结果与恢复](../Ai/ResultsAndRecovery.md)处理。不要自动删除资产、清除锁或强制关闭不明归属的 UE 进程。

交给另一位开发者或 AI 时，说明当前版本、已完成步骤、失败位置、文件位置和下一步。配套手册和这次调用记录应足够还原问题。

已关闭的旧版 AI 安装可以按原完成收据核身份后升级；仅 enabled 位的明确关闭保持可识别，其它身份变化或无完成收据仍拒绝。不会清锁或改写旧收据，当前调用和进程门槛保持。
