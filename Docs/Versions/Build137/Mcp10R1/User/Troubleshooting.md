# 问题处理

## 输入与名称

| 看到什么 | 怎样处理 |
| --- | --- |
| 输入检查失败 | 找完整报告的字段、节点或连接诊断，保留原输入；修明确原因再检查，不生成 |
| 同名目标/request冲突 | 同完整包或项目request已经使用；确认原结果后用“准备新副本”，不覆盖 |

## 按钮与生成结果

| 看到什么 | 怎样处理 |
| --- | --- |
| 按钮不可用 | 插件正在处理操作，或缺少该动作需要的恢复稿、读取内容、导出基线、成功输入、有效资产或报告；查对应按钮的可用条件 |
| 资产已保存，waitingPersistence | 编译保存阶段已过，独立重开未验；使用原输入与收据新PID Verify |
| 结果过期 | 草稿改变后旧结果不能证明当前稿，不点旧定位当当前成功 |
| 日志提示 `/Engine/Transient` 不存在、跳过扫描 | 插件检查或导出会使用不保存的临时内存对象。这条准确路径没有磁盘包，跳过扫描属于正常情况，本期正式导出与原生检查已证明没有阻断操作；材质导出成功时界面也会显示解释。其它路径、错误或失败仍按完整报告处理，不根据黄色图标一概忽略 |

## AI 连接与未知结果

| 看到什么 | 怎样处理 |
| --- | --- |
| MCP 环境阻塞 | 当前 UE 未准备、版本不符、连接占用或配置缺失；先核准确原因，不自动清锁、强杀或替换 DLL |
| 更新后仍提示旧连接 | 新版桥能在旧任务和编辑器正常结束后接续已批准版本；请让AI先核新版本索引，再连接新编辑器。日常DLL/节点资料更新无需反复开关 |
| 提示服务代码需要重新加载 | 这次更新改变了MCP服务程序或依赖本身；载入服务一次即可。它与普通插件/资料更新不同，不默认重启整个应用 |
| pending/unknown | 可能已提交或写入；让 AI 停止后续写入并查询原调用，保留输入和完整报告，不更换身份重发 |
| 报告超限 | 让 AI 按返回的分段导航继续读取；不能把截断内容当成完整成功结果 |

完整报告、请求收据和资产是证据，不能清理掉失败报告制造“通过”。只有确认未提交且原因解决才允许一次有限恢复。源、草稿、基线不清或需扩大支持时停下说明。
