# 版本发布

NodeForge 使用 `v主版本.次版本.修订号` 标识产品版本。v0.1.0 是首个可用版本；本版增加引擎级安装与 AI 一次接入。插件与可选 AI 接入包在同一个 GitHub Release 发布，并明确支持的 UE 版本和平台。

## 发布内容

| 内容 | 用途 |
| --- | --- |
| 插件 ZIP | 放入 UE 工程后使用，包含插件核心及其必要文件 |
| AI 接入 ZIP | 提供连接服务、固定运行环境、配置工具和配套手册 |
| `ReleaseManifest.json` | 记录版本、支持环境、附件和 SHA256 |
| `Checksums.sha256` | 下载文件的完整性校验值 |

用户入口使用简洁的版本和文件名，例如 `NodeForge v0.2.0`、`NodeForge-0.2.0-UE5.3.2-Windows.zip` 和 `NodeForge-AI-0.2.0-Windows.zip`。组件可以保留自己的技术版本，但不应替代产品版本成为下载入口的名称。

## 发布步骤

1. 确定这次版本的功能、支持环境和已知限制。
2. 从实际插件取得节点目录和操作定义，更新对应 Schema、工具契约和节点文档。
3. 核对源码、插件二进制、目录、AI 服务、运行环境和文档的版本与 SHA 是否匹配。
4. 按改动范围完成真实路径检查。插件安装、AI 新装和补装都应使用准备发布的包。
5. 将安装包写入新目录，检查文件清单和校验值，排除工程缓存、个人配置、会话凭据和测试工程。
6. 写好安装指南与 Release 说明。内容应直接说明新增能力、安装步骤、支持环境和已知问题，链接必须能被目标读者打开。
7. 上传同一 Release 的所有附件，回读文件名、大小、SHA 和下载地址，并检查两种安装入口。

插件核心或接口改变后，应发布新版本。已经使用中的文件与来源报告需要保持可追溯，不通过改写校验值把不匹配的组件拼在一起。

## 文档与服务更新

文档索引、页面、目录和工具说明由 Manifest 绑定。仅修改说明时也要更新页面字节数和 SHA，并实际读取更新后的文档，避免页面修改后被服务拒绝。

连接服务的代码、工具契约和批准配置必须相互匹配。兼容的应用代码可以在同一 SDK 进程中重新载入；SDK、解释器或连接核心不兼容时需要重启服务。更新前确认没有未完成写入，更新后重新连接并读取当前工具与资料。更新不会清除 `unknown` 或 `pending`，也不会自动重放调用。

更多兼容规则见 [兼容与升级](../Version/CompatibilityAndMigration.md)。
