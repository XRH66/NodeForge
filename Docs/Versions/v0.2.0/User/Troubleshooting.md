# 错误提示与处理

## 安装与打开面板

| 现象 | 处理方法 |
| --- | --- |
| Window 菜单没有 NodeForge | 在插件管理器中启用插件；检查 `NodeForge.uplugin` 是否位于引擎的 `Engine/Plugins/Marketplace/NodeForge`；高级工程级位置为 `Plugins/NodeForge`，不要重复安装 |
| 提示模块缺失或版本不匹配 | 使用 Release 中的插件 ZIP，确认引擎为官方 UE 5.3.2、系统为 Windows 64 位 |
| 首次打开要求确认路径 | 核对当前工程和引擎位置，点击“确认当前工程并开始使用” |
| AI 安装提示工程正在运行 | 保存并关闭准备安装的目标工程，再运行安装工具 |

## 输入与生成

| 现象 | 处理方法 |
| --- | --- |
| 输入检查失败 | 打开完整报告，找到具体字段、节点或连线错误，修改后重新检查 |
| 目标名称或 requestId 已使用 | 先确认原生成结果，再点击“准备新副本”使用新名称 |
| 按钮不可用 | 等待当前操作结束；确认这个按钮所需的输入、读取结果或导出来源已经存在 |
| 修改输入后，结果显示过期 | 重新检查当前输入。上次结果对应修改前的内容 |
| `waitingPersistence` | 资产已保存，尚未在重新启动编辑器后检查；这不是保存失败 |
| `pending` 或 `unknown` | 保留输入和报告，先查询原操作，不要继续重复生成 |

生成后若需要自动检查重开后的内容，使用原输入和原报告，按 [结果检查说明](../Ai/ResultsAndRecovery.md) 操作。

## 读取资源或导出失败

源资产需要已经保存、没有未保存改动，并位于允许读取的目录。一次只能选择一个支持的资源。插件不能导出包含未知节点或不支持结构的完整图。

`sourceMemoryUnproven` 表示插件无法确认当前已加载对象与保存文件一致。先处理需要保留的未保存改动，正常关闭当前编辑器，再正常打开并连接新的会话。在新的编辑器中先让 NodeForge 读取源资产，然后再手动打开它；不要通过强制重载或自动保存来绕过这个提示。

日志中的 `/Engine/Transient` 指临时内存对象。仅针对这个路径的“文件不存在”或“跳过扫描”提示通常无需处理；仍应查看本次操作的最终结果。其他路径的读取错误需要按报告排查。

## AI 没有看到工具或无法连接

1. 检查安装结果中的客户端配置路径，确认它就是客户端实际读取的文件。
2. 刷新客户端工具列表；客户端要求重启时，重新加载配置。
3. 让 AI 读取 NodeForge 文档索引，确认服务已加载。
4. 若能读文档但不能读工程状态，检查目标 UE 是否正常打开、插件已启用且首次确认完成；多个工程时明确选择。
5. 若提示版本不匹配，核对插件和 AI 接入包是否来自同一 Release。

遇到同名客户端配置冲突时，先确认原配置的用途，需要保留时为新安装指定不同的 `-ServerName`。

安装中途失败时查看返回的 `receipt` 安装记录；它会列出已执行的步骤和错误原因。不要删除整个工程后重试。

## 反馈问题时提供什么

附上 NodeForge 版本、UE 版本、操作步骤、完整错误信息和相关 JSON。报告中如有本机路径或私人资源名称，可以先遮去与问题无关的部分。无需上传整个 UE 工程。
