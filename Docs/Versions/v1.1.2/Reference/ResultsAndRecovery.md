# 保存检查与错误处理

生成后先查看任务状态和报告。预检通过表示输入符合当前规则；生成、编译、保存以及在场景中运行各有独立结果。

## 看懂结果

| 返回结果 | 含义 | 下一步 |
| --- | --- | --- |
| 预检 `succeeded` | 输入通过预检，尚未创建资产 | 检查目标路径，然后生成 |
| `waitingPersistence` | 生成和保存步骤已结束，尚未在重新启动的编辑器中检查文件 | 保留输入与生成记录，按下面的方法检查保存结果 |
| 准备副本 `notBuilt` | 已准备新的请求和目标，尚未生成，也没有预留名称 | 查看差异，再预检和生成 |
| `staleRevision` | 草稿已被修改，当前调用使用的修订号过期 | 重新读取草稿和状态，核对变化后再操作 |
| `pending` | 调用仍在处理 | 使用原 `callId` 查询状态 |
| `unknown` 或 `requiresReview` | 当前信息不足以判断写入结果 | 停止新的生成，先查看原调用和报告 |

报告按步骤记录输入检查、构建、编译、保存等结果。请同时查看错误信息和已创建资产的路径；出错后不能直接假定工程没有发生变化。

## 检查磁盘中的保存结果

保存后的独立检查使用 `verifySaved`。保留生成时的 JSON 输入和收据，正常关闭该编辑器，再使用同一插件版本启动新的编辑器进程检查保存文件。具体调用见[准备与保存检查](../Ai/Preparation.md)。

这个操作检查已经保存的资产，不会重新导入或再次生成。运行逻辑、材质画面和打包效果仍需要在 UE 中另行查看。

## 调用中断时

1. 记录原 `callId`、请求编号、输入文件、报告和资产路径。
2. 用 `calls.get` 查询原调用。不要用新的编号重复提交同一生成任务。
3. 如果进程仍在运行，等待原调用返回；不要通过强制结束进程来重试写入。
4. 检查报告中已完成的步骤、可能留下的资产或文件，再决定下一步。

会话重新连接后，旧 `handle` 和 `reportId` 不再可用。重新连接不等于撤销旧操作，也不会自动重放旧调用。

## AI 如何读取报告

三种编号用途不同：MCP 请求编号用于客户端通信，`callId` 用于查询插件调用，`requestId` 用于标识生成请求。不能互换。

`report_read` 使用本会话返回的 `reportId`，并通过 JSON Pointer 选择需要的字段。例如 `/checks`、`/initialReadback`、`/finalReadback`、`/publishedReadback`；具体名称以该报告实际返回的字段为准。

普通选择结果最多 32 KiB。出现 `resultTooLarge` 时，根据返回的 `navigation.keys` 或 `navigation.length` 继续选择更小的字段，工具不会截断内容。完整图导出使用专用的 `/exportedRequest` 读取方式，最多 64 KiB。原始报告最大为 1 MiB。

每次修改草稿后重新读取修订号，在后续调用中使用实际返回的 `expectedDraftRevision`。同一个 `callId` 不能换成不同的操作或参数。控制服务最多保留 128 次调用，连接服务最多登记 256 份报告；已完成的记录会自动回收；未解决调用应先按原编号查询，不通过重连绕过。
