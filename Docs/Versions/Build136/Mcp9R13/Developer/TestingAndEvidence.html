按影响验证和证据

原理与开发1 个章节约 3 分钟

公开副本中的请求、目标、进程、会话及来源报告身份为虚构示例；历史产品结论保持，原始证明由维护者内部保留。实际调用须使用本次分配和返回的完整原 text/sourceRef，示例身份与零摘要不能作为来源证明。

先核改动：只有工具说明/文档/Python发布器时不重编UE。真实C++修改才准备新Build，按Environment实际UE5.3.2/UBT/已有构建脚本命令定点编译，不能为编号而构建。SDK保持依赖锁，外部参考先核固定来源/许可，不能安装整套项目作为验证。

选择验证层：静态知识/链接/指纹；SDK协商/工具元数据；当前Codex真实加载；生成结构/编译/保存；独立新PID Verify；实际运行；材质画面；打包。每层如实passed/notRun/notApplicable，不能用源码连续性假称新Build运行通过。原M/S/A/P3有限业务和P4安全资料刷新按未变组件复用，新增帮助/发布器另验自己的变化。

需要资产回归时复用专用验证工程，先读ControlRuns台账/activeRun/累计文件哈希/工程独占，按AiPreparation分配一次功能/批次子目录和新完整身份。固定可靠输入/独立预期，保留原图语义。普通重试、换PID或用例不新建工程，工程≤20建议≤12；requestId与资产叶名1–64 ASCII字母数字；目标根下最多两层子目录且每层1–16字母数字，公开限额不收紧。

生成后核原输入digest、身份、checks、initial/final/published readback、磁盘资产和请求收据；只有需要持久化结论才正常结束本次自有UE、核独占，新PID同stage原CLI Verify，不Import/resave。运行/画面/打包另需范围和实际检查。失败先复核写入，查原call/CLI/报告，不换ID重发、强杀或清锁；修真实缺陷只重测受影响项。

每步保存Review输入/版本/SHA、影响、原证据、真实输出、failed/notRun、原call/残留、保护、canAdvance、停止理由和下一条；通过才下一步。Reports存历史，ProjectStatus/Handoff存当前。原Verification逐精确identity/config匹配，experimental不能由文档数量升级verified。

已验证基础与当前候选

旧B/C/J/N/BT/AS的终态按未变组件复用，精确版本范围见发行说明，原完整报告留维护库；交付包EvidenceIndex提供受控限定摘要，不要求普通安装者导入测试工程。当前候选PC3原生成与同stage新PIDVerify属于Repair3，Repair4仅渲染宿主IsClient条件修复；其余79原生源和正式生产核心连续。独立解压入口/模块、固定GPU、唯一最小无生成器副本、Win64实际pak及包后运行各有新证据，不以旧结果代替。

资料修改检查维护源→完整合法输入→同源HTML/搜索/全部链接与闭包→真实当前客户端全文/SHA→必要浏览器阅读样本；公开附件与二进制需要单独核隐私、身份和实际影响。不得仅因Manifest生成就声称内容或最终产品通过。当前完整产品验收由本有限Goal的必需项决定，不扩到全部组合、第二机或其它平台。
