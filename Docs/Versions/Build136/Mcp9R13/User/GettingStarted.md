# 开始使用

## 1. 确认使用的版本

本手册对应 NodeForge-Build136-Mcp9R13，核心 Build136 Repair6。根安装与 RC1 的实际版本从项目状态核对。本版由 InstallationManifest 的受测产品字节和操作者选择工程的私有绑定确定安装身份。首次使用先按[解压与安装](Installation.md)完成 bind/check；不从公共手册推断工程权限，也不自动升级其它安装。

## 2. 打开插件面板

1. 打开已准备好的对应版本工程。
2. 在 UE 的 **Window（窗口）** 菜单选择 **NodeForge**。

若没有这个入口，检查工程是否启用正确插件与模块。正在运行时不要替换插件 DLL。

## 3. 载入完整输入

选择一种方式：

- 点击 **载入 JSON 文件**，选择完整文件。
- 把完整 JSON 放到剪贴板，点击 **粘贴剪贴板**。

正式提交前使用新的完整资产目标和 requestId，避免与已有结果冲突。

## 4. 检查并生成

1. 点击 **检查输入**，查看诊断。
2. 检查通过、目标确认为新资产后，点击 **生成新资产**。
3. 如果修改了输入，先重新检查。

检查不会生成资产或预留名称。需要再生成一份时，先点击 **准备新副本**，确认新目标，再检查和生成；准备副本本身也不预留名称。

## 5. 查看结果

- **打开完整报告**：查看输入、生成、编译和保存的各阶段结果。
- **定位资产**：在内容浏览器找到当前结果。
- **打开资产**：进入 UE 资产编辑器。

定位或打开资产不代表独立核验已经通过。

## 6. 判断是否需要独立核验

若结果是 **waitingPersistence**，表示资产已保存，独立重开核验尚未完成。

具备本机工具权限的操作者或 AI 应正常退出本次自有 UE，确认工程独占后，使用原输入、原生成报告、同一插件版本和新的进程进行 Verify。运行、材质画面和打包是另外的验证层级；本手册不会要求重复已有可靠测试。

## 工程与名称

普通重复试用复用同一个工程，用子目录区分功能与批次。

| 名称或路径 | 当前规则 |
| --- | --- |
| UE 工程名 | 不超过 20 字符，建议不超过 12 字符 |
| 测试资产目录 | `/Game/NodeForgeTests/` 下的功能、批次子目录 |
| 资产短名与 requestId | 1–64个ASCII字母或数字；无下划线、连字符或空白 |
| 根后的子目录 | `/Game/NodeForgeTests/` 后最多两层，每层1–16个ASCII字母或数字；最终资产短名可到64字符 |
| 重复身份 | 同完整目标或已使用的 requestId 会被拒绝 |

用户指定未来组织目录名 NodeFroge。这个名称不代表本版已经开放对应的 UE 挂载路径；目前仍在批准的测试目录生成。
