AI 调用手册5 个章节约 33 分钟

NodeForge把受控JSON转换为可编辑UE资产。先调用nodeforge_docs_index，再用nodeforge_docs_read读取Readme、AiQuickStart和FeatureMap，确认bundle/Build/桥/DLL/目录身份。资料无需UE；业务需要操作者显式准备并注册当前专用编辑器，再connect。只开放契约中的工具，不支持全部UE节点、循环、数组或生产写入。调用完成和资产最终核验不同；waitingPersistence需原CLI新PID Verify。pending/unknown立即停写，查询原calls.get，不换ID重发。开发原理/源码/扩展/发布见DeveloperReadme。

nodeforge_report_read

从当前会话原报告按pointer取得可核验的原生子树。 前提：handle、已登记reportId、RFC6901 pointer；无需新callId/修订。 参数：handle: connect返回的当前桥会话opaque handle；不得复用历史值。; reportId: 当前handle已登记的64位小写hex报告ID，来自原业务返回reports。; pointer: RFC6901 JSON pointer，最多1024字符；空串选择整报告，超限用返回导航逐段读。 /exportedRequest按64KiB完整Graph专用配方取得原text及sourceRef。 效果：只读原报告，最大1MiB；普通pointer选择32768字节，/exportedRequest专用分支交付完整原Graph text（UTF-8最大65536字节）与来源引用；不截断或让用户拼字段。 判据：passed给value；/exportedRequest额外给原text、payloadSha256和sourceRef，显式载入只取text及其中两个报告引用字段；其它超限给navigation/selectionReturned=false。 资料pageId：AiResultsAndRecovery, AiApiReference, AiAssetRead。当前版从docs_index确认；unknown/pending停写查原call。
