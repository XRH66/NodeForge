# 让 AI 使用 NodeForge

先按 [连接 AI](AiInstallation.md) 安装接入包，并让客户端加载配置。AI 接入包包含运行环境、连接服务和本版文档；不需要自己填写开发环境路径。

## 1. 确认连接

先发送一个只读取状态的请求：

> 请读取 NodeForge 的使用说明，连接到我指定的 UE 工程，并告诉我当前插件版本、工程位置和可用操作。

AI 可以通过 MCP 离线读取插件文档。读取工程状态、查询工程资源和生成资产时，UE 需要已经启动并建立连接。安装工具的 `-Connect` 参数可以完成启动和连接检查；MCP 工具本身不负责安装或启动 UE。

## 2. 描述你要做的效果

说明资产类型、预期效果和需要使用的资源。例如：

> 帮我创建一个普通材质，使用颜色参数控制底色，使用数值参数控制粗糙度。先查询本版支持的节点和引脚，检查输入，再生成新资产。告诉我资产保存在哪里。

或者：

> 帮我创建一个 Actor 蓝图，在 BeginPlay 时输出一段文字。先确认当前支持的事件和函数，再生成；保留已有资产。

AI 应先查询实际支持的节点与参数，再编写 JSON。任务需要纹理、父材质或函数时，请提供真实资源路径，或让 AI 在允许的目录内查询。

## 3. 修改已有图

可以这样给出任务：

> 读取我指定的材质，导出支持的完整节点图，把粗糙度参数改为 0.6。先展示差异，再生成一份新资产，保留原材质。

源资产必须已保存、没有未保存改动，且图结构能够完整导出。AI 应通过插件读取原图，保留来源后修改；不能靠猜测节点内容来代替读取。

## 4. 查看结果

AI 应说明生成资产的名称和位置、检查或编译错误，以及是否已经保存。你可以在 UE 中打开资产，继续检查材质效果或蓝图行为。

| AI 返回的状态 | 含义 |
| --- | --- |
| 输入检查通过 | JSON 符合当前检查规则，尚未生成资产 |
| `waitingPersistence` | 资产已保存，尚未在重新启动编辑器后检查 |
| 独立保存检查通过 | 在新的编辑器进程中，用原输入和报告检查了已保存资产 |
| `pending` 或 `unknown` | 原操作尚未有明确结果，应先查询原操作 |

保存成功不包含所有场景中的运行和渲染检查。若原操作结果未知，让 AI 读取原调用和报告，不要换名重复生成。

## 常见操作范围

AI 可以查询节点、读取支持的资源、准备和检查 JSON、生成资产、导出支持图、准备新副本和预览差异。自动重排仍由面板中的 **按上次成功输入重排新副本** 完成；材质实例没有专用 MCP 操作。

客户端需要具备调用 MCP 工具的能力。安装、启动和正常关闭 UE 还需要本机执行权限；这些权限不会因为客户端支持 MCP 就自动获得。
