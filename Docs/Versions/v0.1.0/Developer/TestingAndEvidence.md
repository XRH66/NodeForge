# 验证改动

验证要回答用户实际遇到的问题。先确定修改影响了哪一层，再选择检查范围。

| 改动 | 应检查什么 |
| --- | --- |
| 文档与链接 | 文字是否准确、链接是否可达、示例参数是否与当前接口一致 |
| MCP 参数或连接服务 | 工具发现、参数校验、结果状态、真实客户端调用 |
| 节点或资产字段 | 原生类型与默认值、合法和非法输入、生成、回读、编译和保存 |
| 保存或来源处理 | 原始输入和报告、文件指纹、目标冲突、独立重开检查 |
| 运行行为 | 在 UE 中运行并观察实际结果 |
| 材质画面或打包 | 渲染结果或独立打包后的实际运行 |

文档修改通常不需要重编译 UE。C++ 修改应在支持的 UE 5.3.2 环境重新构建，再验证受影响路径。已通过且实现未变的检查可以复用；不能把静态检查、编译、保存和运行合并成一个结论。

## 资产检查

使用单独的测试工程和未占用目标，记录输入文件、`requestId`、`assetPath`、调用 ID 和生成报告。生成后检查 `checks`、各次回读、文件 SHA 和请求收据。

要确认保存后可以重新加载，先正常结束生成进程，再用同一个插件和原始输入运行 `graphs.verifySaved`。命令见 [准备与保存核验](../Ai/Preparation.md)。不要重新生成或保存资产来代替这一步。

出现 `pending`、`unknown` 或部分写入时，先查询原调用，保留已产生的文件。修复原因后只补测受影响项。

## 记录结果

记录版本、环境、输入、操作、预期、实际结果和必要日志。未运行的部分标明未验证；失败记录和原始报告应保留。提交问题或改动时，优先提供最小可复现步骤，不要求读者拥有维护者的电脑或内部工程。
